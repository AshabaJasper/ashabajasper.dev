# Architecture

## One app, three hosts

```
request  ->  src/middleware.ts  ->  resolveSite(Host)  ->  rewrite /<site><path>  ->  src/app/<site>/...
```

| Host | Site | Internal folder |
| --- | --- | --- |
| `ashabajasper.dev` (and unknown hosts, the health check) | portfolio | `src/app/portfolio` |
| `www.ashabajasper.dev` | 308 to the apex | none |
| `blog.ashabajasper.dev` | blog | `src/app/blog` |
| `admin.ashabajasper.dev` | admin | `src/app/admin` |

- Every request is rewritten, so a path that already carries a prefix on the wrong host
  (`ashabajasper.dev/blog/x`) becomes `/portfolio/blog/x` and lands on that site's
  `[...missing]` catch-all: a real 404 inside the right layout.
- `/api/*` is not rewritten. `apiAllowedOn()` decides which host may call which API;
  anything else is a 404.
- The middleware does not use the Auth.js wrapper. The wrapper replaces the request origin
  with `AUTH_URL`, which turns rewrites into proxies, and sets CSRF cookies on every host.
  The admin gate reads the session JWT with `getToken()`; the admin layout checks again
  with the full config.
- Origins come from `ROOT_DOMAIN` (`siteOrigin`, `siteUrl`), never from request headers,
  so pages stay static and every absolute URL is stable.
- No file-convention `robots.ts`, `sitemap.ts` or `opengraph-image.tsx`: they would emit
  prefixed URLs. Each site has route handlers for `robots.txt`, `sitemap.xml` and `og`.
- The middleware matcher skips `_next/`, static file extensions (images, fonts, CSS, JS,
  `webmanifest`, `pdf`) and any 32-hex `.txt` file, which is the IndexNow key in
  `public/`. Other `.txt` and `.xml` paths are not skipped on purpose: `robots.txt`,
  `llms.txt`, `sitemap.xml` and `feed.xml` are per-site routes and must be rewritten.

## Search and AI discovery

| Route | Hosts | Code |
| --- | --- | --- |
| `/robots.txt` | portfolio, blog, admin | `src/app/<site>/robots.txt/route.ts`. Public hosts use `robotsBody()` from `src/lib/crawlers.ts`: `User-agent: *` allowed, then a group naming the AI crawlers in `AI_CRAWLERS` as allowed, a pointer to llms.txt and the sitemap. The portfolio disallows `/contact/thanks`. The admin returns `Disallow: /`. |
| `/sitemap.xml` | portfolio, blog | `src/app/<site>/sitemap.xml/route.ts` |
| `/llms.txt` | portfolio, blog | `src/app/<site>/llms.txt/route.ts`, both calling `buildLlmsTxt()` in `src/lib/llms.ts` |
| `/llms-full.txt` | portfolio | `src/app/portfolio/llms-full.txt/route.ts`, calling `buildLlmsFullTxt()`: CV data, case studies, every project and every post's MDX body |
| `/feed.xml` | blog | `src/app/blog/feed.xml/route.ts` |

- **Structured data:** `src/lib/structured-data.ts` builds JSON-LD around a single
  Person `@id` (`personSchema`), so every node points at the same entity:
  `websiteSchema` (WebSite), `profilePageSchema` (ProfilePage), `breadcrumbSchema`
  (BreadcrumbList). The case study page (`src/app/portfolio/work/[slug]/page.tsx`) adds a
  CreativeWork and the post page (`src/app/blog/[slug]/page.tsx`) a BlogPosting, both
  pointing at the same `PERSON_ID`. `jsonLd()` serialises the nodes for a
  `<script type="application/ld+json">`.
- **Identity links:** `src/components/shared/identity-links.tsx` adds `rel="me"` links to
  the owner's profiles and email, `rel="author"` to `/about`, and an `alternate` link to
  `/llms.txt`.
- **IndexNow:** the key file is a static file in `public/` (excluded from rewriting, see
  above). Submissions are a manual step after a deploy (DEPLOYMENT.md section 12).

## Data

- Blog posts: MDX files in `content/posts`, validated with Zod at build time
  (`scripts/check-content.ts`) and in tests.
- Portfolio facts: `src/data/profile.ts`, `src/data/work.ts` (47 projects, 5 featured
  case studies), `src/data/experience.ts`, `src/data/cv.ts`; tech logos in
  `src/data/tech-logos.ts`, generated by `npm run logos`.
- The CV download is a static file, `public/cv/Ashaba-Joshua-Jasper-CV-2026.pdf`.
- Admin data: Postgres through Prisma (`prisma/schema.prisma`): the single owner, trusted
  devices, login attempts, audit log, contact messages, comments.

## Cookies

| Host | Cookies |
| --- | --- |
| portfolio, blog | none (no `Set-Cookie` observed on 8 October 2026). Theme preference is localStorage; the terminal intro and the dismissed sticky bar use sessionStorage. Analytics, once Umami is deployed, is cookieless. |
| admin | Auth.js session and CSRF cookies, `ajd_device` trusted-device cookie. All strictly necessary, host-only. |
